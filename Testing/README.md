# Test execution prerequisites and fixture contract

This supports Test_Plan.md v1.0. The 44 active cases are Not Run. The target-method QA adapter and most planned features do not exist yet. This is not a runnable end-to-end test suite or proof of compliance. Existing tests/test_study.py remains separate from TC-001 through TC-051.

## Prepare an isolated run

1. Choose a new temporary directory, never the real `data/study.sqlite3` or the student's original files.
2. Run `python Testing/make_fixtures.py --output <temp-directory>`. Python and ReportLab generate synthetic inputs; no app operations or fault tests are executed by that command.
3. Pin the app commit, Python/dependency versions, model artifact digest/options and screen-reader/browser/OS versions in `run.json`. Copy the fixture manifest into the evidence directory.
4. Implement the QA adapter alongside the component tests before executing target-method cases. It seeds records into a new test database, resolves the aliases below, freezes time, captures outgoing requests and supports the named fault hooks. It calls the specification's named Python methods and adapts legacy HTTP/wire formats explicitly; it does not expose test hooks on the release API. Missing adapter, method, artifact or environment is Blocked when execution is attempted.
5. For each trial reset the isolated fixture database/files, choose a fresh request/event ID except in explicit retry tests, and save `results/<run-id>/<TC-ID>/` with input, expected/actual, timestamps, environment, synthetic logs and defect link. Preserve the first failure before rerunning. Never claim the fixture generator ran the product checks.

## Aliases and repeatable actions

- F1 is seed.json: CA/CB are different courses; SA/SB are their respective sessions; NA is CA's immutable original note. NOTE and its SHA-256 are the committed-content oracle. Source deletion tests use a separate managed PDF source, not NA, so intentional cleanup is not mistaken for unintended note loss.
- F1 already has one CA note (NA), one CB note (NB), and the declared matching passage records; it has no stored cards initially. TC-001 adds exactly one new CA note, leaving NA unchanged. MC is a card recipe until created. Practice cases TC-009/022/046 must create/accept MC as a prerequisite and retain its returned item ID; draft-gating cases TC-004/038/039 start without accepted cards. For TC-025 create course/source/card through the clean UI rather than injecting seeded database rows.
- `reset F1` means create a fresh test store, seed the declared IDs/current revisions through its fixture helper and copy readable.pdf to a generated app-owned managed path. Query current library/settings versions before calls that require them. Remove none of the student's originals.
- When a case says "plus managed PDF source", the fixture helper creates a separate CA PDF source, its located passage/index entry and an accepted dependent card, with the managed copy under the app-owned test directory. The fixture readable.pdf outside that directory is the original whose hash must remain unchanged. This factory is a QA-adapter prerequisite, not an already implemented production method.
- P1/P2/P3 are CA passages with deterministic IDs; PB belongs to CB. F2 uses the ready synthetic digest D1, Q=(1,0,...), P1/P2=(1,0,...), P3=(0,1,0,...). Expected scores are 1,1,0 and tie order is P1 then P2; PB must not be returned. Unit profiles are trusted test doubles only, not proof a real model is local. For the empty-course trial create CE through createCourse and use its returned ID without adding sources.
- MC is the manual card in seed.json; D_OK is the supported candidate. NA/P1 need matching source/passage records before reference tests. For a successful open-reference path retain accepted item/source IDs. Confirmed source deletion cascades to its dependent item in TC-037, so resolving that now-absent item ID must return NOT_FOUND. SOURCE_GONE applies when an identified item/reference survives but its evidence is unavailable. Neither condition may substitute another source. A "missing course" input uses a valid UUID absent from the seed, not a malformed identifier.
- N100/N100000/N100001 are repeated ASCII N strings of exactly those lengths. F3 isolates byte, page and extracted-character validators with controlled parser outputs, keeping the other limits valid. Image-only/zero-text and corrupt parser paths use empty.pdf/corrupt.pdf; no OCR result is fabricated. The target 100,000-character rule versus the prototype's 300,000-byte JSON cap is a known compatibility gap for large Unicode payloads that the adapter/implementation must resolve and document, not silently ignore.
- T0 is 2027-03-01T12:00:00Z. Reset the state for each rating trial; use old interval 0 for initial good and 20 for capped doubling. Call reveal first. The same event ID/payload must return the original result; changed payload under that ID is a conflict.
- F4 is F4_passages.json: materialize all 5,000 passage/vector records (1,000 per course) using the referenced 768-D vectors before timing. Do not time a small JSON list or include embedding/import work in the note-save measurement. Record a separate cold/warm description; all ten saves, not only the average, must meet the target.
- Initialize `window.__qa_executed=false` before displaying HTML_JS. Check literal textContent, absence of newly created img/script nodes and the unchanged sentinel; CSP blocking alone is not proof the text was rendered inertly.

## Fault and measurement hooks

Fault_Catalog.json defines F01-F10, each run against a fresh F1. The QA adapter uses fake parser/model outputs, an exclusive SQLite lock, process stop before publication, a failing migration and an exclusive managed-file handle. Close test handles after collecting evidence. Model deadlines use a deterministic clock: the request must be aborted by 60.000 simulated seconds; log OS/UI presentation overhead separately rather than loosening the requirement. Save latency uses perf_counter_ns around the save call/ack, with raw samples.

Model-quality trials fix corpus, prompt, profile digest/options and run three repeated prompts. Locality tests capture app/runtime requests and require a downloaded, verified local profile or a controlled loopback stub; do not download weights during the measured run. Human support/clarity/usefulness labels for at least 20 real candidate outputs remain future work. Record disagreements; a matching quote does not establish logical entailment or a learning gain.
